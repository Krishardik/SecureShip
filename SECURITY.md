# Security Policy

## Reporting a Vulnerability

If you discover a potential security vulnerability in SecureShip, please
report it privately rather than publishing exploit details in a public issue.

Use GitHub's private vulnerability reporting feature for this repository
if it is enabled. Otherwise, contact the repository maintainer through
their GitHub profile to arrange private disclosure.

Please include the following information where possible:

- A description of the suspected vulnerability.
- The affected endpoint, component, or configuration.
- Steps to reproduce the issue in a controlled environment.
- The potential security impact.
- Any suggested mitigation or remediation.

Do not include real credentials, access tokens, personal information,
or other sensitive data in your report.

## Scope

Security reports may cover authentication, authorization, input validation,
session and token handling, sensitive data exposure, API abuse, dependency
vulnerabilities, container security, and CI/CD pipeline weaknesses.

Only test systems and environments you own or have explicit permission
to assess. Do not access, modify, or delete another person's data.

## Response and Disclosure

The maintainer will review reports as time permits. Please allow an
opportunity to investigate and address a confirmed issue before publicly
disclosing technical details.

This policy does not guarantee a response time or a particular remediation
timeline.
